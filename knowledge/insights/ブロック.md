# ブロックの調べ方（2026-08-13・本人の臨床手順）

## 中核

**主訴はたいてい抽象のまま来る。抽象のままでは除去できない。**
だから2段で割る。

```
主訴（抽象）      … 「働きたくない」
　↓ ①何が嫌なのかに割る
内訳（具体）      … 責任・肉体疲労・対人・役立たず
　↓ ②なぜそう思うのかを鑑別する
原因（除去対象）  … トラウマ／解離性障害／世代間連鎖／前世障害
　↓
除去
```

本人の言葉：**「この辺りを調べて除去してく」**

※ これは `rubric.md`「★AIに任せきれない2点」①の具体と抽象そのもの。
　 読者は抽象で悩んでいて、**抽象を除去できる一点まで割るのが施術者の仕事**。
　 rubric「提供価値は的を出す事」を、工程として書き下したものになる。

## 出てくるタイミング＝「次の欲求」

本人の言葉：**「最初は体調不良を主訴としてた人が、次の欲求として言ってくる事が多い」**

つまりブロックは入口の主訴ではない。**体調が戻った後に出てくる第二層。**

```
体調不良で来る → 良くなる → 次の欲求（働きたい／稼ぎたい／人に会いたい）が出る
　　　　　　　　　　　　　　　　↓
　　　　　　　　　　　　　　ブロックを調べて除去
```

- ルートCLAUDE.mdの **「3万到達＝ロイヤルカスタマー」の実態がこれ**。
  継続する理由は「まだ症状が残ってるから」ではなく、**次の欲求が出てくるから**
- `stock_経過と卒業.txt` の一段先。卒業ではなく、**卒業した後に何を頼まれるか**
- rubric「目的を体調に閉じない」（★整えすぎない・10）の裏付けになる一次情報

## 投稿にする時（※ここから下は提案。本人未確認）

### 使い方A：予後として見せる（勧誘に効く／推し）
1行目を「働きたくない人へ」にしない。**読者の現在地は体調**なので、ズレる。
しかも「普通に働きたくないだけの人」を集めると、肛門・ナイトソックスと同じ罠になる。

- ✅ 1行目は「体調が戻った人が、次に言い出す事があります」の側
  → 予後が見える＝ DM→3万の段に直接効く（rubric ⑤の出口・予後の一行）

### 使い方B：怠け扱いを外す
**「働きたくないは、怠けじゃなく4つのどれか」**。
rubric「読者を意志の問題にしない」の強い実装になる。内訳4つを並べるだけで成立する。

### 使い方C：自己分類させる（検証枠）
「働きたくない」は誰にでも経験があり、作業ゼロで4分岐に分かれる。
rubric ③の最上位形（クラクション型）の条件を満たす。
締めは「番号でいいから、リプで教えてくれ」。

## 対象になるブロック（2026-08-13・本人回答で確定）

本人「**ブロック除去は沢山の人が興味持つ。ニーズ強い**」。
「働きたくない」は1テーマではなく、**入口の一例**だった。同じ2段（内訳→原因）で割れる対象は他にもある。

| ブロック | 内訳の例（仮。テーマごとに要作成） |
|---|---|
| 働きたくない | 責任・肉体疲労・対人不安・役立たず不安 |
| **結婚** | 見捨てられる不安・支配される不安・自分の親のようになる不安・幸せになる事への罪悪感 |
| **お金** | 稼ぐと嫌われる不安・使うと無くなる恐怖・貰う事への罪悪感・親の金銭感覚の刷り込み |
| **対人不安** | 拒絶される予期・顔色を伺う癖・自分の意見を持つ事への恐怖 |

→ **「ブロック除去」自体を独立ジャンルとして扱ってよい。**
　 内訳4つ・原因4系統（トラウマ／解離性障害／世代間連鎖／前世障害）という
　 **同じ骨格を使い回せる**のが強み。テーマを変えても構造は変えない。

※ 内訳は仮置き。テーマごとに実際の相談内容と合ってるか本人確認してから固定する
　（rubric.mdの「判定軸を発明しない」と同じ扱い。特に結婚・お金は未検証）
